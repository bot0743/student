Классификация

Нагрузочное, стрессовое, объёмное, стабильность

Нагрузочное

Поведение под ожидаемой нормальной и пиковой нагрузкой (100, 500, 1000 пользователей).

Стрессовое

За пределами ожидаемой нагрузки — до отказа. Поиск предела прочности и поведения при сбоях.

Объёмное

Работа с большими объёмами данных (миллион товаров, поиск, отчёты).

Стабильность (soak)

Длительная нагрузка (сутки/неделя) — выявление утечек памяти, деградации.

Что измеряем

Метрики производительности

Время отклика (response time)

Среднее, 95-й процентиль, 99-й. Критично для UX.

Пропускная способность (throughput)

RPS (requests per second), TPS (transactions per second).

Одновременные пользователи

Активные сессии, моделирование реального поведения.

Загрузка ресурсов

CPU, RAM, I/O, сеть — поиск узких мест.

Количество ошибок

Таймауты, 5xx, сбои соединения.

TTFB / полная загрузка

Время до первого байта, загрузка всех ресурсов.

Генераторы нагрузки

Apache JMeter, Yandex Tank, мониторинг

Apache JMeter

Настольное приложение на Java. Позволяет создавать тестовые планы, настраивать количество потоков, сценарии, таймеры, собирать результаты.

  • HTTP, JDBC, FTP, SOAP и др.
  • Группы потоков (Thread Group)
  • Слушатели (Listeners) — графики, таблицы
  • Распределённое тестирование

Другие инструменты

Yandex Tank — автоматизация, интеграция с мониторингом.

Мониторинг сервера: PerfMon (Windows), top/htop/iostat (Linux).

Пример структуры тест-плана JMeter

Тест-план
└── Группа потоков (100 пользователей, ramp-up 60 с)
    ├── HTTP-запрос (главная страница)
    ├── Таймер (пауза 2-5 с)
    ├── HTTP-запрос (каталог)
    ├── Таймер (пауза 3-7 с)
    ├── HTTP-запрос (добавление в корзину)
    └── Слушатель (таблица результатов, график)

Защита от атак

DoS/DDoS, rate limiting, resource exhaustion

DoS / DDoS

Стресс-тест показывает, при какой нагрузке система падает. Помогает настроить защиту.

Rate limiting

Ограничение числа запросов с одного IP — проверяется нагрузочным тестированием.

Resource exhaustion

Уязвимости, вызывающие аномальное потребление ресурсов (например, тяжёлый поиск).

Нагрузочное тестирование помогает выявить «узкие места», которые могут быть использованы злоумышленниками.

Лабораторная работа

JMeter: создаём нагрузку на учебное приложение

Разделимся на группы: одна группа генерирует нагрузку на приложение другой группы.

  • Сценарии: главная страница, поиск, добавление в корзину.
  • Измеряем время отклика, пропускную способность, ошибки.
  • Стресс-тест: увеличиваем нагрузку до отказа, фиксируем предел.
  • Мониторинг сервера (CPU, RAM) во время теста.

Проводится в изолированной среде, локально, с возможностью перезапуска.

Первый тест в JMeter

Теория

Изучить понятия нагрузочного тестирования, метрики, виды тестов.

Практика

Установить JMeter. Создать тестовый план для своего учебного приложения: 10 пользователей, сценарий: открыть главную → каталог → карточка товара. Запустить, сделать скриншоты результатов (график времени отклика, таблица).

На следующей практике — разбор результатов и сложные сценарии.
