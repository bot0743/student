Отличие от функционального

Функциональное vs Безопасность

Функциональный тестировщик проверяет, что пользователь может успешно авторизоваться. Тестировщик безопасности проверяет, может ли злоумышленник авторизоваться без пароля, получить доступ к чужому аккаунту, украсть данные или положить систему.

Последствия уязвимостей: утечка данных, кража денег, репутационные потери, штрафы.

Словарь

Уязвимость, угроза, риск, вектор атаки

Уязвимость

Слабое место в системе (например, отсутствие проверки прав, SQL-инъекция).

Угроза

Потенциальная возможность реализации уязвимости злоумышленником.

Риск

Вероятность реализации угрозы × размер ущерба.

Вектор атаки

Путь использования уязвимости (HTTP-запрос, вредоносный скрипт и т.д.).

Главный бесплатный инструмент

OWASP ZAP (Zed Attack Proxy)

Перехватывающий прокси-сервер. Встраивается между браузером и приложением, позволяет перехватывать, анализировать и модифицировать HTTP-запросы/ответы.

  • Пассивное сканирование (анализ трафика)
  • Активное сканирование (атака приложения)
  • Перехват и модификация запросов на лету
  • Автоматизация через API

Пример перехваченного запроса

POST /login HTTP/1.1
Host: example.com
Content-Type: application/x-www-form-urlencoded

username=admin&password=12345

Можно изменить данные перед отправкой (например, добавить SQL-инъекцию).

Другие инструменты: Burp Suite Community, Nikto, SQLmap, WPScan, OWASP WebGoat (учебное приложение).

Основные проверки безопасности

IDOR / нарушение доступа

Изменение id в URL (profile?id=123 -> 124) — должен быть отказ.

site.com/profile?id=124

XSS (межсайтовый скриптинг)

Ввод <script>alert('XSS')</script> в поля. Если скрипт выполняется — уязвимость.

SQL-инъекции

Кавычка ' или ' OR '1'='1 — ошибка БД или неверная авторизация.

Сессии и куки

Флаги HttpOnly, Secure, SameSite; истечение сессии; защита от кражи.

CSRF

Проверка наличия anti-CSRF токенов в формах и их валидации.

Конфигурация

Стандартные пароли, открытые порты, отладочные режимы, подробные ошибки.

Практика · Охота на баги

Перекрёстное тестирование проектов

Каждая группа получает приложение другой группы и ищет уязвимости:

  • SQL-инъекции
  • XSS
  • Нарушения доступа (IDOR)
  • Ошибки конфигурации
  • Проблемы сессий

Найденные уязвимости оформляются как security-баг-репорты с шагами воспроизведения, влиянием и рекомендациями.

Этика: тестируем только то, на что получено разрешение, в изолированной среде, не наносим реального ущерба.
