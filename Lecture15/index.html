Качество установщика

Что проверить в .msi?

Чистая установка

На новую систему: папки, файлы, ярлыки, запуск.

Обновление (upgrade)

Сохранение пользовательских данных и настроек.

Удаление

Полное удаление без мусора (файлы, реестр).

Нестандартный путь

Пробелы, кириллица, диск D: — всё должно работать.

Недостаток места

Предупреждение, отказ от копирования.

Без прав администратора

Запрос UAC или понятная ошибка.

Восстановление (repair)

Восстановление повреждённых файлов.

Автоматизация проверок

PowerShell скрипты

Тихая установка (msiexec /i /quiet), проверка файлов, запуск тестов, удаление.

CI/CD пайплайн

Каждый коммит → сборка .msi → развертывание на чистой ВМ → smoke-тесты → отчёт.

# Пример PowerShell для проверки установки
Start-Process msiexec -Wait -ArgumentList "/i app.msi /quiet"
Test-Path "C:\Program Files\MyApp\app.exe"
Start-Process "http://localhost:5000"
# ... проверка статуса
msiexec /x {product-guid} /quiet

Инструменты: GitHub Actions, GitLab CI, Jenkins, Ansible.

Автоматизация → повторяемость → уверенность
Непрерывная интеграция

Пример workflow

name: Build and Test Installer
on: [push]

jobs:
  build-and-test:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4
      - name: Build .msi with WiX
        run: candle.exe product.wxs && light.exe product.wixobj
      - name: Install silently
        run: msiexec /i setup.msi /quiet
      - name: Smoke test (HTTP)
        run: curl -f http://localhost:5000
      - name: Uninstall
        run: msiexec /x setup.msi /quiet

✅ Бесплатно для публичных репозиториев (GitHub Actions). Каждый пуш — проверка установки.

Критерии готовности установщика

Нет блокирующих дефектов установки/удаления
Все тесты установки пройдены на целевых ОС (Win10/11)
Время установки ≤ 2 мин на типичном ПК
Цифровая подпись (Code Signing) — доверие пользователя
Сканирование OWASP ZAP и антивирусами — 0 критических уязвимостей

Если хотя бы один критерий не выполнен — релиз откладывается.

Качество — это не случайность, это результат
Безопасность инсталляции

Цифровая подпись (Code Signing)

Зачем подпись?

Гарантирует, что файл не изменён после подписания. Убирает предупреждение «Неизвестный издатель». В корпоративной среде без подписи блокируется политиками.

Как получить?

Code Signing Certificate от доверенного удостоверяющего центра (Comodo, DigiCert). Подпись через signtool или встроенные средства WiX.

signtool sign /fd SHA256 /a /tr http://timestamp.digicert.com myinstaller.msi

Тестировщик должен проверять, что установщик подписан и подпись действительна.

Безопасность начинается с доверия к инсталлятору
Современный путь

Docker вместо .msi

Преимущества

Один образ — везде одинаково. Лёгкость, масштабируемость, отсутствие проблем с зависимостями.

Тестирование образа

Запустить контейнер → проверить порт → прогнать API-тесты. Всё автоматизируется в CI/CD.

docker build -t myapp .
docker run -d -p 5000:5000 myapp
curl http://localhost:5000/health

Это направление — мощный шаг в карьере (DevOps, SRE).
