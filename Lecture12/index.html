Business Process Reengineering

Фундаментальное переосмысление

Реинжиниринг — это не «улучшим то, что есть», а отказ от старого и создание процессов заново, с использованием современных технологий. В разработке ПО это переход от «водопада» к гибким методологиям и непрерывной поставке.

Цель: радикальное улучшение стоимости, качества, скорости и обслуживания.

Скорость vs Качество

Раньше и сейчас

Раньше

Релиз раз в полгода. Длительное ручное тестирование. Успевали проверить всё вручную.

Сейчас

Релизы каждую неделю или день. Ручной регресс займёт недели. Без автоматизации — никак.

Автоматизация перестала быть «плюшкой» — это суровая необходимость для выживания на рынке.

Пирамида автоматизации

UI-тесты (мало, дорогие, хрупкие)
API-тесты (быстрые, стабильные)
Интеграционные тесты
Модульные тесты (основа, много, дёшево)

Чем выше уровень, тем меньше тестов, но они медленнее и дороже.

Основа качества — быстрые и надёжные модульные тесты.

Ошибка: начинать автоматизацию с UI. Правильно — идти снизу вверх.
Окупаемость инвестиций

Когда автоматизация выгодна?

Частота прогонов

Автоматизация окупается, если тесты выполняются многократно (регресс, smoke на каждый билд).

Время на поддержку

Тесты — это код. Плохие тесты превращаются в технический долг.

Формула

ROI = (экономия от ручного выполнения × количество прогонов) − (затраты на разработку + поддержку).

Непрерывная интеграция и доставка

CI/CD как результат реинжиниринга

commit
unit tests
API tests
UI tests
security scan
deploy

Пример .github/workflows/test.yml

name: CI
on: [push]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - name: Run unit tests
        run: dotnet test
      - name: Run API tests (Newman)
        run: newman run collection.json
      - name: Run UI tests (Selenium)
        run: mvn test
Безопасность встроена

DevSecOps: безопасность в CI/CD

SAST (статический анализ)

Поиск уязвимостей в коде при каждом коммите.

DAST (динамический анализ)

Сканирование работающего приложения.

Автоматизация безопасности

Позволяет находить уязвимости на ранних этапах, когда их исправление стоит копейки.

Не всё гладко

Flaky-тесты, поддержка, время

Flaky-тесты

Нестабильные тесты, падающие без причины. Их отключают, и ценность теряется.

Долгое выполнение

Если тесты идут часы, они замедляют конвейер. Нужно оптимизировать.

Сложность поддержки

Тесты — код, требуют рефакторинга, код-ревью, хороших паттернов.

Стабильные локаторы, разумные ожидания, изоляция, отчёты со скриншотами.

Практика · Финальный проект

Строим конвейер для учебного приложения

  • GitHub Actions: при каждом пуше запускаем модульные тесты.
  • Newman: запуск коллекций Postman.
  • UI-тесты (Selenium) на headless-браузере.
  • Статический анализ безопасности (например, OWASP Dependency Check).
  • Автоматический деплой на тестовый стенд при успехе.

Вы увидите, как автоматизация превращает разработку в единый поток.
