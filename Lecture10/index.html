Почему это важно

Первое взаимодействие с продуктом

Установка — это первое, с чем сталкивается пользователь. Если она проходит гладко — положительные эмоции. Если падает, требует неизвестных библиотек или удаляет файлы — доверие потеряно.

Тестирование установки (installation testing) проверяет успешность установки, настройки, обновления и удаления в целевой среде.

Технологии создания

Типы инсталляторов

Portable

Простое копирование файлов, без записи в реестр и системные каталоги.

InstallShield / WiX

Профессиональные инструменты, создают setup.exe или MSI-пакеты.

Inno Setup / NSIS

Бесплатные, гибкие скриптовые инсталляторы.

MSI (Microsoft Installer)

Поддержка транзакционности, отката при сбое, централизованное управление.

Что проверяем

Направления тестирования установки

Чистая установка

На чистую ОС: запуск, экраны мастера, создание файлов/реестра, запуск приложения.

Обновление (upgrade)

Поверх предыдущей версии, сохранение данных и настроек, миграция.

Нестандартные условия

Мало места, нет прав, нестандартный путь, национальные символы, другой язык ОС.

Удаление

Через панель управления, удаление всех файлов/записей (без мусора), сохранение пользовательских данных.

Восстановление после сбоя

Имитация сбоя (отключение питания, убийство процесса) — проверка отката.

Данные — самое ценное

Тестирование миграций

Миграция схемы БД

Изменение структуры таблиц, преобразование данных, проверка целостности.

Миграция конфигураций

Перенос настроек пользователя в новый формат.

Миграция пользовательских файлов

Перенос документов, изображений в новую структуру папок.

Как тестировать: копия продакшен‑базы (обезличенная), накат миграции, проверка всех функций и данных. Проверка идемпотентности, прерывания, восстановления.

Вектор атаки

Безопасность установки и обновлений

Цифровая подпись

Инсталлятор должен быть подписан, подпись действительна. Неподписанный вызывает предупреждения.

Права доступа

После установки файлы и папки должны иметь минимально необходимые права (не давать на запись всем).

Безопасность обновлений

Автообновление по HTTPS, проверка целостности, защита от подмены (MITM).

Сброс настроек безопасности

Обновление не должно откатывать патчи безопасности или ослаблять политики.

Лабораторная работа

Тестирование установки учебного приложения

  • Чистая установка на чистую ВМ/компьютер.
  • Проверка создания файлов, записей реестра.
  • Установка в нестандартную папку, на диск с малым местом, под пользователем без прав.
  • Тестирование удаления (остался ли мусор).
  • Если есть обновление — проверка сохранности данных.
  • Проверка подписи инсталлятора, прав доступа к файлам.

Чек-лист и тестирование

Теория

Составить чек-лист для тестирования установки (не менее 20 пунктов: чистая, обновление, удаление, негативные, безопасность).

Практика

Выполнить чек-лист на своём учебном приложении, задокументировать результаты (скриншоты, описание проблем).
