Жизненный пример

Всё работает, но не у всех

Разработчики на Windows 11 + Chrome. Пользователи жалуются: у кого-то не открывается корзина, у кого-то съезжают кнопки. Выясняется: Windows 7 + IE11, macOS + Safari, медленный интернет.

Окружение разное — поведение разное. Задача тестировщика — выявить проблемы до продакшена.

Что влияет на работу ПО?

Факторы конфигурации

Аппаратное обеспечение

Процессор, ОЗУ, видеокарта, модель устройства (ПК, мобильное).

Операционные системы

Windows, macOS, Linux, Android, iOS, версии, сервис-паки.

Браузеры

Chrome, Firefox, Safari, Edge, версии, движки рендеринга.

Стороннее ПО

СУБД, веб-серверы, библиотеки, зависимости.

Сеть

Скорость, задержки, тип подключения (Wi-Fi, мобильный), прокси, файрволы.

Региональные настройки

Язык, форматы даты/времени, валюта, часовой пояс.

Настройки приложения

Конфигурационные файлы, флаги функциональности, параметры.

Проблема

Комбинаторный взрыв

5 ОС × 3 браузера × 2 версии БД × 2 аппаратных конфигурации = 60 комбинаций. Добавьте региональные настройки — и получите тысячи.

5 3 2 2 60

Тестировать всё невозможно — нужно выбирать.

Стратегии выбора конфигураций

Анализ целевой аудитории

Кто наши пользователи? Статистика браузеров, ОС, регионов. Тестируем самые популярные конфигурации.

Анализ рисков

Какие конфигурации наиболее проблемны? Старые версии, экзотические устройства, ограниченные ресурсы.

Попарное тестирование (Pairwise)

Покрываем все пары значений параметров. Большинство дефектов вызывается взаимодействием двух параметров.

PICT (Microsoft)

Критичные для заказчика

Конфигурации, которые точно будут на продуктиве, тестируем максимально тщательно.

Практика

Этапы проведения

1

Планирование

Определить параметры, выбрать значения (тестовые конфигурации).

2

Подготовка среды

Виртуальные машины, облака, докер, реальные устройства.

3

Выполнение тестов

Ручные или автоматизированные прогоны на каждой конфигурации.

4

Анализ результатов

Сравнение поведения, фиксация дефектов, связанных с конфигурацией.

Инструменты: VirtualBox, VMware, Docker, BrowserStack, Sauce Labs, Selenium Grid, Charles Proxy.

Совместимость

Браузеры и операционные системы

Chrome / Edge (Blink)

Наиболее популярны, но версии отличаются. Автообновление — плюс, но старые версии ещё в ходу.

Firefox (Gecko)

Свой движок, свои особенности CSS/JS. Может работать там, где Chromium ошибается.

Safari (WebKit)

Основной браузер на macOS/iOS. Строгие политики безопасности, отличия в рендеринге.

Различия в поддержке CSS Grid, Flexbox, API, обработке событий — нужно тестировать!

Не только код

Региональные форматы и сеть

Дата и время

ДД.ММ.ГГГГ vs MM/DD/YYYY — ошибки валидации, неправильное отображение.

Валюта и числа

Разделители тысяч и десятичной части: 1.234,56 vs 1,234.56.

Скорость сети

Имитация 2G/3G/4G, высокие задержки — проверка таймаутов, индикаторов загрузки.

Прокси и файрволы

Приложение должно корректно работать через корпоративные прокси.

Инструменты: Chrome DevTools (Throttling), Charles Proxy, Fiddler.

Безопасность ≠ константа

Конфигурация и безопасность

Настройки безопасности браузера могут блокировать скрипты, куки, iframe.

Права доступа в разных ОС — приложение может не иметь прав на запись в папку.

Разные версии библиотек имеют разные известные уязвимости.

Корпоративные сети с прокси и строгими политиками могут нарушить работу API.

Лабораторная работа

Конфигурационное тестирование

Задание: Проверить работоспособность учебного приложения в разных браузерах (Chrome, Firefox, Edge), с разными региональными настройками и в условиях медленной сети.

  • Прогнать ключевые тест-кейсы (авторизация, добавление товара, оформление заказа).
  • Изменить региональные форматы (дата, число) в ОС и проверить отображение.
  • Использовать DevTools для имитации медленной сети (3G).
  • Зафиксировать расхождения, оформить баг-репорты.

Оборудование: ПК с Windows 10, установленные браузеры.
